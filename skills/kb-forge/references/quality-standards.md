# "有思想"文档的质量标准

来自用户自身写作的标准提炼。这不是一般性的"好文章"标准，而是特定于"改变读者心智模型"这一目标的检查维度。

## 六个必要维度

### 1. 论点驱动（Thesis-Driven）

文档必须有一个可争论的核心主张。不是"X 有哪些特点"，而是"X 在 Y 条件下优于 Z，但会在 W 条件下失败"。

**测试**：把核心主张发给一个聪明的人，他会说"有道理但我想挑战你的假设"，而不是"嗯，这是常识"。

**反模式**：
- "本文介绍了 X 的方方面面" → 没有论点，是百科
- "X 很重要" → 没有 specificity，谁都会说
- "X 比 Y 好" → 缺条件限定，过于绝对

**正例**：
- "DutyAI 选择 SQLite 而非 Redis 做任务队列，因为在单机 + 写入量 <100 QPS 的场景下，运维简单性的价值远超 Redis 的吞吐优势——而这个场景至少持续到用户数破 1000"

### 2. 决策树（Decision Tree）

读者带着不同的前提条件来看文档。好文档让每个读者能快速定位"我的情况应该怎么选"。

**格式**：
```
如果你的情况是 A：
  → 选方案 1，因为...
如果你的情况是 B：
  → 选方案 2，但注意...
如果你不确定自己是 A 还是 B：
  → 先检查 <具体指标>，如果 >阈值 则是 A
```

**维度选择**：决策树的分支条件应该是读者能在 5 分钟内确认的事实（团队规模、日请求量、是否有 DBA），而非需要深入研究才能判断的特征。

### 3. 证据密度（Evidence Density）

每个关键论据必须有可追溯的数据支撑。

**好的证据**：
- "Anthropic 多 agent 研究系统使用 15x token 开销，但性能提升 90.2%"（可追溯到 anthropic-engineering.md §3.2）
- "field-notes #24 的安全隔离修了 5 轮，从全锁死到逐步放开"（可追溯到代码 commit）

**差的证据**：
- "大家都知道 SQLite 适合小项目" → 没有 specificity
- "根据经验" → 谁的经验？什么场景？

**引用格式**：行内标注 `(source: <具体来源>)`。如果是 kb/ 内容标注文件名和章节号，如果是外部来源标注 URL。

### 4. 风险与反论（Risks & Counter-arguments）

显式列出"什么情况下这个结论是错的"。

**结构**：
```
### 风险与反论

**反论 1**：有人会说 <相反观点>。
**回应**：在 <条件> 下确实如此。但本文的前提是 <条件>，在此前提下 <为什么反论不成立>。

**风险 1**：如果 <假设变化>，本文结论的 <具体哪部分> 将不再成立。
**缓解**：<能做什么来提前发现这个风险>。
```

**不能做的事**：
- 只列风险不给缓解 → 制造焦虑而非帮助决策
- 只列弱反论（稻草人）→ 降低可信度
- 不列风险 → 读者会自己想到然后不信你的结论

### 5. 行动导向（Action-Oriented Ending）

结尾是 action items，不是 summary。读者读完应该知道"下一步做什么"。

**格式**：
```
## 下一步行动

**立即可做**（本周）：
1. <具体行动> — 预期效果：<...>
2. <具体行动> — 预期效果：<...>

**条件触发**（当 X 发生时）：
3. <具体行动> — 触发信号：<...>

**长期监控**：
4. 关注 <指标/信号>，当 <阈值> 时重新评估本文结论
```

### 6. 时效投影（Temporal Projection）

知识有保质期。好文档明确标注"这个结论现在成立是因为 X，当 Y 变化时需要重新评估"。

**格式**（文末必须包含）：
```
**时效判断**：
- 核心前提：<列出 1-3 个关键假设>
- 有效期估计：<时间范围或条件>
- 失效信号：当看到 <具体可观察信号> 时，<哪些结论> 需要更新
- 下次审查建议：<日期或触发条件>
```

## 跨领域综合（Cross-domain Synthesis）

这是锻造区别于摘要的最高层能力：将看似无关的领域连接起来，产生新的理解。

**操作方法**：
1. 从主题领域提取**结构**（不是内容）
2. 在另一个领域找到**同构结构**
3. 检验同构是否产生了**新洞察**——类比必须教给读者某个在原领域内看不到的东西

**示例**：`os-memory-hierarchy.md` 将操作系统存储层次映射到知识管理架构。这不只是比喻，而是产出了具体设计原则（CLAUDE.md = 寄存器，kb/ = RAM，recall = page fault handler）。

**反模式**：
- 强行类比两个不相关的东西（"AI 就像小孩学习" → 结构不同构，会误导）
- 类比停在"很像"而不产出 actionable insight
