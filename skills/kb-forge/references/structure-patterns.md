# 文档结构范式

根据主题性质选择骨架。不要混用——每种骨架解决不同类型的问题。

## 骨架 A: 决策分析（Decision Analysis）

**适用于**：需要在多个方案中选择（技术选型、架构决策、策略方向）

```
# [决策标题]

## 一句话结论
<在 [条件] 下选 [方案]，因为 [核心理由]>

## 背景与约束
<决策发生的上下文、不可改变的约束条件>

## 方案对比
### 方案 A: [名称]
- 优势：<具体>
- 劣势：<具体>
- 最佳场景：<什么条件下选它>
- 实际案例：<谁在用，效果如何>

### 方案 B: [名称]
（同上结构）

## 决策树
<如果你的 X 是...则选...; 如果你的 Y 是...则选...>

## 风险与反论
<...>

## 下一步行动
<...>

## 时效判断
<...>
```

## 骨架 B: 原则提炼（Principle Extraction）

**适用于**：从散落的经验中提炼出可复用的原则（从 field-notes → 架构哲学）

```
# [原则名称]

## 核心主张
<一句话：这个原则是什么，为什么重要>

## 观察到的现象
### 现象 1: [标题]
<field-notes #N 的具体事件，精简到关键信号>

### 现象 2: [标题]
<另一个事件>

（至少 3 个独立现象支撑同一个原则）

## 从现象到原则
<这些看似不同的事件，底层共享什么结构？>
<用交叉领域类比加深理解（如适用）>

## 原则的应用边界
<什么时候适用？什么时候不适用？>

## 对 DutyAI 的具体影响
<这个原则如何改变我们做决策的方式>
<决策树：遇到类似情况时的选择路径>

## 下一步行动
<...>

## 时效判断
<...>
```

## 骨架 C: 技术深潜（Technical Deep-Dive）

**适用于**：深入理解一个技术概念并提出实践指南（从 anthropic-engineering → DutyAI 实践）

```
# [技术概念]: 从理论到 DutyAI 实践

## 核心主张
<这个技术概念对我们意味着什么，不是"它是什么">

## 概念精要
<最简化的概念解释，只保留与应用相关的部分>
<去掉"一般性科普"，聚焦"改变你做决策的那部分">

## DutyAI 现状对照
<我们现在在这个维度上做了什么？做得如何？>
<对照概念评估：哪些做对了，哪些有差距>

## 实践指南
### 场景 1: [具体场景]
<When → Do → Expected outcome>

### 场景 2: [具体场景]
<When → Do → Expected outcome>

## 量化预期
<实施后的预期改善，用数字表达>

## 风险与反论
<...>

## 下一步行动
<...>

## 时效判断
<...>
```

## 骨架 D: 事后复盘（Post-Mortem Synthesis）

**适用于**：从一个或多个事件中提取战略教训（比 field-notes 更深一层）

```
# [事件/主题] 复盘

## 一句话教训
<不是"发生了什么"而是"这意味着什么">

## 时间线
<精简到关键节点，每个节点标注决策点>

## 关键决策分析
### 决策 1: [描述]
- 当时选了：<...>
- 为什么选这个：<当时的信息和约束>
- 事后看：<对/错 + 为什么>
- 如果重来：<会怎么选>

### 决策 2: [描述]
（同上）

## 结构性根因
<超越"哪一步做错了"——是什么系统性因素导致这类错误会发生？>

## 防御体系设计
<不是"下次注意"，而是"建什么机制来自动防御">

## 下一步行动
<...>

## 时效判断
<...>
```

## 选择指南

```
用户意图                → 骨架
"A 和 B 选哪个"         → A (决策分析)
"这些经验说明了什么"     → B (原则提炼)
"这个技术/理论怎么用"    → C (技术深潜)
"这次踩坑学到了什么"     → D (事后复盘)
"帮我想清楚这个问题"     → 先确认是决策问题(A)还是理解问题(B/C)
```
