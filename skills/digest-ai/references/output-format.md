# 输出格式规范

## 大佬动态（置顶高亮块）

如果数据源 0 抓到了有实质内容的 AI 领袖推文，在日报**最前面**输出高亮引用块：

```
> **AI 大佬动态**
>
> **Sam Altman** (@sama): "引用原文或概括"。[原推](https://x.com/sama/status/xxx) | [配图](图片URL)
> **Yann LeCun** (@ylecun): "引用原文或概括"。[原推](https://x.com/ylecun/status/xxx)
```

规则：
- 只收录有实质信息的推文，不收录空泛表态
- 每人最多 1 条，整个区块最多 5 条
- 每条必须附原推链接
- 有信息量的图片附 `[配图](图片URL)`
- 当天无值得报道的推文 → 跳过此区块
- 与编号条目相关时交叉引用

## 正文条目

- 只挑最重要的 5-8 条，宁缺毋滥
- 标注「新发现」或「持续跟踪」
- 中文输出
- 当天没大事 → 直接说「今天没有特别值得关注的动态」
- **保留热度数据**：HN 的 points/comments、GitHub 的 star 数、HuggingFace 的 upvote 数
- 完成后保存到 `$TASKPOOL_USER_DESK/digest-ai/YYYY-MM-DD.md`

### 每条必须包含的信息层

每条不是"转述新闻标题"，而是要让读者看完就有判断力。**必须包含以下 3 层**：

1. **发生了什么**（1 句）— 事件本身
2. **核心观点/关键数据**（1-2 句）— 这条消息里最有信息量的一个点。可以是：
   - 一个关键数字（性能提升多少、融资多少、用户量多少）
   - 一个核心论点/争议点（作者的核心主张是什么、社区争论焦点是什么）
   - 一个具体案例（谁用了什么、产生了什么结果）
   - 一个技术突破点（解决了什么之前解决不了的问题）
3. **为什么值得关注**（1 句）— 对行业/读者的影响判断

**反例（禁止）**：
- ❌ "《Vibe Coding 彻底杀疯了》报道 Vibe Coding 概念爆火，普通人通过自然语言编程成为可能。" — 只有第 1 层，没有核心观点和具体案例
- ❌ "HuggingFace Daily Papers 热门论文：Mobile-Agent-v3.5 (32 upvotes)" — 只有标题+热度，不知道论文做了什么

**正例**：
- ✅ "少数派报道 Vibe Coding 概念爆火。文章核心案例：一位非程序员用 Claude Code 两天搭出完整 SaaS 产品并上线收费，验证了'自然语言即编程语言'的可行性。这标志着 AI coding 工具的用户群正从开发者扩展到普通人。"
- ✅ "Mobile-Agent-v3.5：首个跨 Android/iOS/Web 三平台的 GUI Agent 框架，在 3 个平台的操作成功率分别达到 78%/71%/83%。此前 GUI Agent 都是单平台，跨平台统一是走向通用桌面 Agent 的关键一步。"

### 论文/项目列表条目

当一条新闻包含多个论文或项目时（如 HuggingFace 论文、GitHub Trending），**每个子项也必须用一句话说清核心贡献**，不能只列名字+数字：

- ❌ `- Mobile-Agent-v3.5 — 多平台基础 GUI Agents (32 upvotes)`
- ✅ `- Mobile-Agent-v3.5 — 首个跨 Android/iOS/Web 三平台 GUI Agent，操作成功率 78%+ (32 upvotes)`

### 来源链接质量

- **禁止使用 example.com 或占位符链接**。如果无法找到原始来源 URL，标注 `来源：WebSearch（未找到原始链接）`
- 每条来源必须是可点击的真实 URL

## 链接格式要求

1. **所有链接必须是完整可点击 URL**，使用 markdown 链接格式 `[显示文本](URL)`
2. **HN 来源**：同时提供原文 + HN 讨论链接。格式：`来源：[原文](原始URL) | [HN 讨论](https://news.ycombinator.com/item?id={objectID})`
3. **HuggingFace 论文**：`https://huggingface.co/papers/{paper_id}`，有 arXiv 也附上
4. **GitHub 项目**：`https://github.com/{owner}/{repo}`
5. **X/Twitter 推文**：`https://x.com/{handle}/status/{id}`
6. **少数派文章**：原文页链接
7. **播客集**：该集页面 URL
8. **其他来源**：保留原始网页 URL，不能只写"来源：WebSearch"
9. 每条来源行以 `来源：` 开头，多个链接用 ` | ` 分隔
10. **原则：存档文件必须包含追溯到每条信息源头的完整链接**

## 图片保留

有信息量的图片（产品截图、架构图、benchmark 对比图）在条目末尾附 `[配图](图片URL)`。纯装饰性图片不保留。

## 实体背景补充

每条新闻中出现的关键实体，在**首次出现时**补充 1-3 句背景：

- **人物**：身份 + 核心成就。例："Anthropic CEO，前 OpenAI 研究副总裁"
- **论文/研究**：做了什么 + 为什么是突破
- **开源项目**：技术定位 + 核心特性 + 解决什么痛点
- **公司/产品**：定位 + 创始团队背景 + 差异化
- **播客/信源**：定位 + 嘉宾级别

**判断标准**：非圈内人不能"一看就知道"的实体需要补充。Elon Musk 不需要，Joon Sung Park 需要。

## 信源发现

如果发现不在当前数据源列表中的高质量渠道，在日报末尾追加：

```
## 信源发现

- **[渠道名称]**（URL）— 推荐理由。抓取方式：RSS / Jina Reader / API
```

"高质量" = 内容被引用为核心来源 + 嘉宾/作者级别高 + 稳定更新 + 可抓取。
用户确认后，将新信源写入 SKILL.md 的数据源章节。
