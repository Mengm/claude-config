# Video Digest：视频 → 教学文档

将视频字幕或转录文本转化为高质量的结构化教学文档。核心目标不是"压缩"，而是"重组"——把线性的口语流重组为可扫描、可检索、可讨论的教学材料。

## 为什么需要这个 skill

视频字幕有几个天然问题：
- **碎片化**：自动生成的字幕每条只有 2-4 个词，句子被切碎
- **冗余**：口语有大量重复、停顿、自我纠正
- **无结构**：3 小时的内容是一条平坦的时间线，没有章节、没有层级
- **信息密度不均**：关键洞见可能藏在第 2 小时的某个类比里

这个 skill 的工作是：从碎片中还原完整语义，识别教学结构，保留具体的数字/实验/类比（这些是让人记住内容的锚点），最终输出一份可以替代重看视频的文档。

## 输入格式

支持以下输入：

| 格式 | 说明 |
|------|------|
| `.srt` | SubRip 字幕，最常见（YouTube 下载） |
| `.vtt` | WebVTT 字幕 |
| `.txt` | 纯文本转录稿 |
| 视频 URL | YouTube/B站链接，用 web-read skill 提取字幕 |

## 执行流程

### Phase 1：获取文本

**如果输入是 SRT/VTT 文件：**

运行提取脚本去掉序号和时间戳，保留纯文本和时间信息：

```bash
python ~/.claude/skills/video-digest/scripts/extract_subtitle.py <input_file>
```

输出两个文件到同目录：
- `<name>_transcript.txt` — 纯文本（用于阅读和总结）
- `<name>_timed.jsonl` — 带时间戳的句子（用于章节切分）

**如果输入是视频 URL：**

用 web-read skill 获取字幕文本。YouTube 和 B站都支持字幕提取。

**如果输入是纯文本：**

直接进入 Phase 2。

### Phase 2：识别章节结构

这是最关键的一步。视频的教学结构不在字幕里——需要从内容语义中推断。

**策略：先粗后细**

1. **快速扫描全文**：读取转录文本，识别主题转换点。口语中的主题转换通常有信号词：
   - "OK so now let's talk about..."
   - "The next stage is..."
   - "Moving on to..."
   - "So that's X, now Y"
   - 或者内容本身从一个概念跳到另一个概念

2. **建立章节大纲**：列出 5-15 个章节（取决于视频长度），每章给一个描述性标题。30 分钟视频大约 3-5 章，3 小时视频大约 8-15 章。

3. **如果有时间戳信息**：用 `_timed.jsonl` 文件确定每章的时间范围，方便读者回看原视频。

4. **如果视频本身有章节标记**（YouTube 章节、视频描述中的时间线）：优先使用，但可以细化或合并。

### Phase 3：分章总结

对每个章节，提取以下四层信息：

#### 层 1：核心论点（这章在说什么）

用 2-4 段话概括本章的核心内容。要求：
- 保留讲者的论证逻辑链，不要只列结论
- 如果讲者先提出问题再给答案，保留这个"问题→答案"结构
- 如果讲者对比了两种方案，保留对比结构

#### 层 2：具体锚点（让人记住的东西）

这是区分好总结和烂总结的关键。以下内容必须保留：

- **具体数字**：训练成本、参数量、数据集大小、时间、百分比
- **实验/演示**：讲者做的 live demo、对比实验、失败案例
- **类比**：讲者用来解释抽象概念的比喻（"像 zip 文件的有损压缩"）
- **引用原话**：特别精辟或有争议的原话，用引用格式保留
- **反直觉的结论**：与常识相反的发现

为什么这些重要：人的记忆是靠具体场景锚定的。"GPT-2 训练花了 $40,000，Karpathy 用 llm.c 复现只花了 $672"比"训练成本在下降"有用一百倍。

#### 层 3：关键术语

本章引入的新概念/术语，给出简短定义。格式：
- **术语名（英文原文）**：一句话定义

只收录本章新出现的术语，不重复之前章节已定义的。

#### 层 4：实践启示（可选）

如果本章内容有明确的实践指导意义（比如"遇到计算任务要让模型用代码"），单独列出。不是每章都有，不要硬凑。

### Phase 4：组装文档

按以下结构组装最终文档：

```
# [视频标题]

> 讲者：[姓名和背景]
> 时长：[时长] | 目标受众：[受众]
> 来源：[视频链接]

## 来源说明
[简要说明这份文档的定位——不是逐字翻译，是教学文档]

## 这篇适合谁
[3-4 个 bullet，描述目标读者]

## 读完你应该带走什么
[5-6 个 bullet，描述学习目标]

## 一句话版本
[用一句话概括整个视频的核心论点]

---

## 1. [章节标题]
[核心论点]
[具体锚点：数字、实验、类比]
[关键术语]
[实践启示]

## 2. [章节标题]
...

---

## 关键要点速览
[表格形式，每个阶段/主题一行：核心能力 | 关键局限]

## 核心术语表
[全文术语汇总表]

## 实用资源
[视频中提到的工具、网站、论文、项目链接]

## 讨论题
[3-6 个开放性问题，适合团队讨论]
```

### Phase 5：质量检查

完成初稿后，做以下检查：

1. **信息完整性**：视频中的关键数字、实验、类比是否都保留了？
2. **逻辑链完整性**：每章的论证是否有头有尾，还是只有结论没有推导？
3. **独立可读性**：随机挑一章，不看其他章节能否理解？
4. **实用资源**：视频中提到的工具、网站、论文是否都收录了？
5. **未来展望**：如果讲者谈了未来方向，是否有专门章节？

### Phase 6：输出

**默认输出**：Markdown 文件，保存到输入文件同目录。

**如果用户要求飞书文档**：
```bash
feishu-cli doc import <markdown_file> --title "<标题>" --verbose
feishu-cli perm add <doc_id> --doc-type docx --member-type email --member-id <email> --perm full_access --notification
```

**如果用户要求其他格式**：先生成 Markdown，再转换。

## 语言策略

- 默认跟随用户语言
- 如果用户说中文但视频是英文：中文写作，保留英文术语（首次出现时给中文翻译）
- 术语格式：**中文名（English Term）**
- 引用讲者原话时保留英文

## 处理超长视频的策略

3 小时以上的视频，转录文本可能超过 200KB。处理策略：

1. **分批读取**：每批 3000 行左右
2. **并行总结**：如果有 subagent 能力，按章节分组并行处理
3. **合并校验**：合并后检查章节间的衔接和术语一致性

## 常见陷阱

- **过度压缩**：把 3 小时内容压成 500 字摘要，丢失了所有让人记住的锚点。宁可长一点，也要保留具体性。
- **只有结论没有推导**：写"RLHF 有局限"不如写"Karpathy 用 Pelican 笑话实验说明：RL 优化 1000 步后最佳笑话变成了 'the the the the the'——reward model 给满分但毫无意义"。
- **忽略实验和演示**：讲者的 live demo 往往是最有教学价值的部分。
- **遗漏实用资源**：视频中提到的工具/网站/论文链接是读者最想要的。
- **没有未来展望**：如果讲者谈了趋势和方向，这部分对读者价值很高。
